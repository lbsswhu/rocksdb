本轮全部 96 次运行均在 `lb_rocksdb_16u` 中执行。测试时间：2026-11-24T15:10:34+0800 至 2026-11-24T15:24:44+0800。
CPU quota=1600000/100000，cpuset=0-15；memory.limit 与 memory.memsw.limit 均为 34359738368。无可用 swap 配额，前后 swap/total_swap 均为 0；内存 failcnt、OOM kill 均为 0。

A0：父提交 `4d57a393a8f1563c0dff1ff468756c23d89e3601`。A1：目标提交关闭 ZERO_RANGE；B：目标提交开启 ZERO_RANGE。目标提交为 `0a47210279850a86ee97e8fc1dae846d4a110db3`。
复用已核验干净源码、提交信息、相同 Release 编译参数的构建；二进制和动态库 SHA256、实际动态库路径保存在 environment.json 与 ldd 日志中。

每种组合/版本预热一次 2 秒，正式三次各 5 秒；结果取正式样本中位数。8 种组合 × 3 组 × 4 次=96 次。配置顺序使用 seed=1001 打乱；每轮循环轮换 A0/A1/B，串行执行。
统一参数：16 前台线程，key/value=16/1024 B，batch=1，无压缩，WAL 开启，memtable/目标 SST=64 MiB，4 个 write buffer，level base=256 MiB，后台 jobs=2，WAL recycling=0，pipelined write=0，buffered I/O，bytes_per_sync/wal_bytes_per_sync=0。
只写为 fillrandom，每次从空库开始；读写为 readrandomwriterandom，50% 读/50% 写，每次复制相同的、完整填入 600000 个 key 的 seed。sync=true 表示每次写要求 WAL 同步，use_fsync=false 使用 fdatasync 路径；多线程可能共享 group commit。
混合 ops/s 为读写总操作数；只写 ops/s 为写操作数。数据集适合缓存，本轮不是超内存数据集测试。

## 波动与结论

异步前台吞吐 B/A0 为 -2.25% 到 -0.42%，没有观察到提升。同步前台 B/A0 为 +1.46% 到 +11.51%，但不能统一解释为整体收益。
只写、sync=true、concurrent=false：B/A1 前台 +20.03%，配对轮次变化 -1.90% 到 +28.21%，波动很大；B/A0 前台 +11.51%，端到端却 -5.30%，提示需关注收尾成本。
只写、sync=true、concurrent=true：B/A0 前台 +5.75%、端到端 +5.62%，提供初步正向信号。读写、sync=true、concurrent=true：B/A1 前台 +5.94%，三轮配对变化均为正；但 B/A0 只有 +1.78%，应区分开关收益与整个提交收益。

## 校验与干扰控制

96 次执行及离线 SST checksum/full scan 均成功；混合负载扫描均为 600000 key。32 次 B 运行均实际触发 WAL、flush、compaction 的 ZERO_RANGE，fallback、allocation failure、truncate failure 均为 0。A1 的 ZERO_RANGE 调用均为 0，目标提交的最终 close 均为 OK。
计时过程中没有并行运行编译、代码搜索、磁盘扫描或其他基准；控制脚本阻塞等待 db_bench，校验/复制/清理均放在计时之外。期间只进行少量轻量进度检查；会话恢复时做过一次 ps/进度检查，后续进度读取绑定在 CPU16（测试 cpuset 0-15 之外）。未进行全局 drop_caches。
未对共享宿主机的其他负载进行强制隔离，不能声称物理意义上的零干扰。每个样本独立 DB；seed 复制会填充文件缓存，所有组采用相同流程。
